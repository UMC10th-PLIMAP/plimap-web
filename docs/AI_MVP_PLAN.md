# AI 접목 MVP 구현 계획서

## 1. 작업 기준

- 기준 브랜치: `develop`
- 작업 브랜치: `feature/ai-mvp-mock`
- 목표: 실제 AI·신규 백엔드 없이 목업 데이터로 전체 사용자 흐름을 시연한다.
- 유지 원칙: 기존 장소 선택, 노래 검색, PIN 등록 API 흐름은 깨지지 않게 유지한다.
- 기술 원칙: 새 패키지를 추가하지 않는다. React, Zustand, 브라우저 Camera/File API, Canvas, Web Share API와 기존 컴포넌트를 재사용한다.
- 데이터 원칙: AI 결과만 고정된 비동기 목업으로 제공하고, 나중에 실제 API 함수로 교체할 경계를 한 파일에 모은다.

## 2. MVP에서 확정할 동작

### 지도 — 캐릭터와 현재 위치 마커

1. MVP 목업에서는 첨부된 캐릭터 3종을 기본 제공하고, 내 PIN 개수 `pinCount`가 10개 늘어날 때마다 캐릭터 1개를 추가 생성한 것으로 간주한다.
2. 추가 캐릭터도 같은 3종을 순환 사용해 중복 생성할 수 있다.
   - `music`: 검정 티셔츠, 분홍 포인트 헤드폰, 음악 버블 배경
   - `night`: 아이보리 니트, 검정 팬츠, 달·필름 배경
   - `summer`: 빨간 모자, 흰 티셔츠, 파란 팬츠, 여름 배경
3. 마이페이지에 `내 캐릭터` 영역을 추가한다.
   - 잠금 해제된 캐릭터 목록을 표시한다.
   - 선택한 캐릭터를 브라우저 저장소에 저장한다.
   - 선택하지 않았거나 잠금 해제 캐릭터가 없으면 기존 현재 위치 마커를 쓴다.
4. 지도에서는 선택한 캐릭터가 기존 현재 위치 원형 마커를 대체한다.
   - GPS 위치 변경은 현재 `watchPosition` 흐름을 그대로 사용한다.
   - 이동감은 CSS 바운스/보행 애니메이션으로 표현한다.
   - 첨부된 지도 예시처럼 캐릭터별 후면 사선 시점 이미지를 사용하고, 방향은 이미지 전체 회전으로 표현한다.
   - 실제 3D 메시 렌더링은 MVP 범위에서 제외한다. Three.js 같은 새 런타임을 넣지 않고 한 장의 마커 이미지로 2.5D 효과를 낸다.

필요 에셋:

```text
public/characters/music-card.png
public/characters/music-marker.png
public/characters/night-card.png
public/characters/night-marker.png
public/characters/summer-card.png
public/characters/summer-marker.png
```

- `*-card.png`: 마이페이지 캐릭터 선택 카드용 정면 전신 이미지
- `*-marker.png`: 지도용 후면 사선 보행 시점 투명 이미지
- 지도 마커 아래에는 기존 네온 현재 위치 원과 방향 삼각형을 유지한다.
- 권장 규격은 투명 배경 WebP와 동일 캔버스 크기다. 첨부 이미지는 디자인 기준으로 확정됐지만 아직 저장소 파일로는 들어오지 않았다.

### 지도 — 사진 분석 후 AI 노래 추천

현재 `MapPage`의 `등록하기` 버튼을 눌렀을 때 장소 정보를 저장한 뒤 바로 노래 검색으로 가지 않고 사진 분석 화면을 한 번 거친다.

```text
장소 선택
  → 등록하기
  → 장소 사진 촬영/선택
  → 분석 중 애니메이션과 "장소의 분위기를 분석하고 있어요"
  → 스토리형 추천 카드: 세븐틴 - 파이팅 해야지
     ├─ 이 노래 선택 → 기존 SongDetailPage
     └─ 건너뛰기 → 기존 SongListPage
```

- 사진 입력: `<input type="file" accept="image/*" capture="environment">`
- 분석 시간: 목업 함수에서 약 1.5초 지연
- 추천 결과: 항상 `세븐틴 - 파이팅 해야지`
- 추천 선택: 고정된 `itunesTrackId`와 재생 준비 데이터를 목업으로 연결한 뒤 기존 노래 상세/등록 UI를 재사용한다.
- 건너뛰기: `/app/song/list`로 이동해 기존 검색 로직을 그대로 사용한다.
- 사진은 서버에 올리지 않는다. 미리보기용 Object URL만 쓰고 화면을 벗어날 때 해제한다.

### 지도 — 장소별 누적 노래 분석

- 서울시청 좌표에 데모 장소와 여러 곡을 추가한다.
- 장소 바텀시트에 `AI 노래 분석` 버튼을 표시한다.
- 누르면 목업 결과를 바텀시트 또는 다이얼로그로 보여준다.
  - 대표 곡 1개
  - 장르 그룹별 곡 수
  - 장소 분위기 한 줄 요약
- 예시 결과:

```text
대표 곡: 세븐틴 - 파이팅 해야지
K-POP / 댄스: 5곡
인디 / 어쿠스틱: 3곡
R&B: 2곡
요약: 출근길에 활력을 더하는 밝고 리드미컬한 음악이 많아요.
```

서울시청 목업은 개발/데모 모드에서만 사용하고 프로덕션 API 데이터와 섞지 않는다.

### 마이페이지 — 친구 장르 궁합

- `UserProfilePage`에만 `장르 궁합 보기` 버튼을 추가한다.
- `MyProfilePage`에는 해당 버튼을 표시하지 않는다.
- 버튼을 누르면 약 1초 동안 분석 상태를 보여준 뒤 목업 결과를 표시한다.
  - 궁합 점수
  - 공통 선호 장르
  - 서로 다른 장르
  - 함께 들을 추천 곡 1개
- 사용자 ID를 seed처럼 사용해 같은 사용자에게는 항상 같은 결과가 나오게 한다.

### 마이페이지 — 대표 음악

- 내 프로필에 카카오톡 프로필 뮤직과 유사한 `대표 음악` 카드를 추가한다.
- 기존 노래 검색 UI/컴포넌트를 재사용해 한 곡을 선택한다.
- 선택 결과는 MVP용 Zustand persist 저장소에 보관한다.
- 대표 음악은 내 프로필에 표시한다. 다른 사용자 프로필은 서버 필드가 없으므로 이번 MVP에서는 목업 대표 곡만 표시하거나 표시하지 않는다.

### 홈 — 주간 AI 리포트

- `HomePage`의 기존 콘텐츠 가장 아래에 주간 리포트 카드를 추가한다.
- 목업 결과:
  - 이번 주 기분 키워드
  - 많이 들은 장르
  - 대표 곡
  - 한 줄 코멘트
- `인스타 공유` 버튼은 웹에서 Instagram 앱을 직접 지정하지 않는다.
  - Canvas로 세로형 공유 카드 PNG를 만든다.
  - `navigator.share({ files })`가 지원되면 OS 공유 시트를 연다.
  - 지원하지 않으면 PNG를 다운로드한다.

### 홈 — 오늘의 AI 노래 추천

- 홈 하단에 주간 리포트와 별도 카드로 추가한다.
- 입력 방식:
  - 기분 칩 선택: 신남, 차분, 지침, 설렘 중 하나
  - 선택 입력: 짧은 프롬프트
  - 현재 날씨/기분/프롬프트를 종합하는 것처럼 분석 상태 표시
- 실제 날씨 API를 추가하지 않는다. 목업 날씨 `맑음 · 22°C`를 사용한다.
- 결과는 기분별 고정 곡 테이블에서 하나를 반환한다.
- 추천 곡 선택 시 기존 곡 상세 또는 검색 화면으로 연결한다.

## 3. 목업 데이터와 상태 설계

과한 서비스 계층을 만들지 않고 아래 두 파일로 시작한다.

```text
src/features/ai-mvp/mockAi.ts
src/features/ai-mvp/useAiMvpStore.ts
```

`mockAi.ts` 책임:

- 사진 분석 추천
- 장소 누적 노래 분석
- 친구 장르 궁합
- 주간 리포트
- 오늘의 추천
- 공통 `delay`와 고정 목업 데이터

`useAiMvpStore.ts`에 영속화할 값:

- 선택한 캐릭터 ID
- 내 대표 음악

캐릭터 잠금 해제 수는 `myProfile.pinCount`에서 매번 계산한다. AI 분석 결과는 고정 데이터이므로 저장하지 않는다.

## 5. 구현 순서

### 1단계 — 공통 목업 기반

- `mockAi.ts`에 데이터와 비동기 목업 함수 작성
- `useAiMvpStore.ts`에 선택 캐릭터와 대표 음악만 저장
- 캐릭터 에셋 경로/타입 정의

완료 조건: 새 API 요청 없이 각 목업 함수가 항상 재현 가능한 결과를 반환한다.

### 2단계 — 사진 분석 PIN 등록 흐름

- 사진 분석 페이지와 라우트 추가
- 지도 등록 CTA를 새 페이지로 연결
- 고정 추천 곡 선택/건너뛰기 분기
- 기존 SongList/SongDetail/Pin 등록 흐름 회귀 확인

완료 조건: 촬영 → 분석 → 추천 선택 또는 건너뛰기 → 기존 PIN 등록까지 끊김 없이 진행된다.

### 3단계 — 캐릭터 선택과 지도 마커

- PIN 개수 기반 캐릭터 목록 계산
- 마이페이지 선택 UI 추가
- 현재 위치 오버레이에 선택 캐릭터 반영
- 방향/이동 애니메이션과 기본 마커 폴백 추가

완료 조건: 선택 즉시 지도 현재 위치 마커가 바뀌고 새로고침 후에도 유지된다.

### 4단계 — 서울시청 장소 분석

- 서울시청 목업 핀/곡 구성
- 분석 CTA와 결과 UI 추가

완료 조건: 서울시청 핀 선택 후 대표 곡과 장르 묶음을 확인할 수 있다.

### 5단계 — 프로필 AI 기능

- 타인 프로필 장르 궁합
- 내 프로필 대표 음악

완료 조건: 내/타인 프로필의 버튼 노출 조건이 정확하고 선택 결과가 유지된다.

### 6단계 — 홈 AI 기능과 공유

- 오늘의 추천 카드
- 주간 리포트 카드
- Canvas 이미지 생성 및 Web Share/다운로드 폴백

완료 조건: 기분/프롬프트 입력으로 추천을 받고, 주간 리포트를 이미지로 공유하거나 저장할 수 있다.

### 7단계 — 검증

```bash
pnpm typecheck
pnpm lint
pnpm build
```

모바일 수동 검증:

- 카메라 권한 허용/거절
- 위치 권한 허용/거절
- 새로고침 후 캐릭터/대표 음악 유지
- 캐릭터 0개, 1개, 3개 이상 해금 상태
- 내 프로필과 타인 프로필 버튼 차이
- Web Share 지원/미지원 브라우저
- 사진 분석 건너뛰기 후 기존 검색/등록 흐름

## 6. 인수 조건

- 실제 AI 서버 없이 모든 AI 기능을 시연할 수 있다.
- 모든 분석 화면에 로딩 상태와 결과 상태가 있다.
- `세븐틴 - 파이팅 해야지`가 사진 분석 추천 결과로 항상 표시된다.
- 기존 노래 검색과 PIN 등록 흐름은 건너뛰기 후 그대로 동작한다.
- 타인 프로필에만 장르 궁합 버튼이 보인다.
- 내 프로필에서 대표 음악과 캐릭터를 바꿀 수 있다.
- 선택한 캐릭터가 현재 위치 마커로 표시되고 위치 갱신을 따라간다.
- 서울시청 목업 장소에서 누적 노래 분석 결과를 볼 수 있다.
- 홈에서 오늘의 추천과 주간 리포트를 볼 수 있다.
- 주간 리포트 공유가 불가능한 브라우저에서도 이미지 다운로드가 가능하다.
- 프로덕션 API 타입과 기존 서버 계약을 변경하지 않는다.
- 새 의존성을 추가하지 않는다.

## 7. 구현 전에 필요한 확인 사항

진행을 막지는 않지만 아래 항목은 확정이 필요하다.

1. 첨부 이미지를 저장소에 넣을 수 있도록 원본 파일 또는 배경 제거된 WebP를 제공할지, 구현 단계에서 배경 제거본을 만들지
2. 실제 3D 모델(`.glb`/`.gltf`)이 필수인지, 첨부된 지도 예시처럼 후면 사선 이미지 기반 2.5D 마커로 MVP 승인이 가능한지
3. `등록하기` 버튼을 사진 촬영 진입점으로 보는 해석이 맞는지
4. 사진을 반드시 직접 촬영해야 하는지, 갤러리 선택도 허용할지
5. 대표 음악을 타인 프로필에도 보여줄지, 내 프로필 데모만 만들지
6. 주간 리포트 공유 카드에 들어갈 로고/문구의 최종 디자인

답이 없으면 이 문서의 기본값으로 구현한다.

# 구현용 프롬프트

아래 프롬프트를 구현 에이전트에게 그대로 전달한다.

```text
현재 저장소의 feature/ai-mvp-mock 브랜치에서 AI 접목 MVP를 구현해줘.

먼저 docs/AI_MVP_PLAN.md를 끝까지 읽고, 기존 지도 → 장소 선택 → 노래 선택 → PIN 등록 흐름과 HomePage, MyProfilePage, UserProfilePage, 현재 위치 오버레이 코드를 확인해. 기존 API 계약은 변경하지 마.

핵심 제약:
- 실제 AI/신규 백엔드 없이 결정적 목업 데이터로 구현한다.
- 새 npm 패키지를 추가하지 않는다.
- 기존 컴포넌트, Zustand, 브라우저 기본 API를 재사용한다.
- AI 목업 함수는 src/features/ai-mvp/mockAi.ts에 모은다.
- 영속 상태는 선택 캐릭터와 내 대표 음악만 저장한다.
- 과한 범용화, 단일 구현용 인터페이스, 미래용 레이어를 만들지 않는다.
- 접근성 레이블, 에러/권한 거절 폴백, Object URL 해제를 생략하지 않는다.

구현 범위:
1. 지도 등록하기 이후 사진 촬영/선택 → 분석 애니메이션 → 항상 "세븐틴 - 파이팅 해야지" 추천.
2. 추천 선택 시 기존 곡 상세/등록 흐름, 건너뛰기 시 기존 노래 검색 흐름으로 이동.
3. PIN 10개마다 캐릭터 한 개 해금. 3종을 순환해 중복 생성 가능.
4. 내 프로필에서 캐릭터 선택. 선택 캐릭터가 지도 현재 위치 마커를 대체하고 위치 이동을 따라감.
5. 서울시청 목업 장소에 여러 곡을 쌓고 AI 노래 분석 버튼으로 대표 곡/장르 그룹/요약 표시.
6. 타인 프로필에만 장르 궁합 보기 버튼과 목업 분석 결과 표시.
7. 내 프로필에 대표 음악 설정 추가. 기존 노래 선택 UI를 재사용하고 선택값 유지.
8. 홈 하단에 오늘의 AI 추천과 주간 리포트 추가.
9. 주간 리포트는 Canvas PNG + Web Share API로 공유하고, 미지원 시 다운로드.

첨부된 캐릭터는 music(검정/분홍 음악), night(아이보리/필름), summer(빨간 모자/여름) 3종이다. 마이페이지에서는 정면 전신 이미지를, 지도에서는 첨부된 지도 예시와 같은 후면 사선 이미지를 사용한다. 에셋 파일이 저장소에 없으면 앱을 깨뜨리지 말고 기존 현재 위치 마커 폴백을 유지한 채 필요한 정확한 파일명을 결과에 알려줘. 실제 3D 엔진은 추가하지 말고 캐릭터별 마커 이미지 한 장과 CSS 애니메이션으로 MVP를 만든다.

작업은 계획서의 단계 순서대로 진행하고 각 단계 후 pnpm typecheck를 실행해. 마지막에 pnpm lint와 pnpm build도 실행해. 실패하면 원인을 수정하고 다시 검증해.

완료 보고에는 변경 파일, 구현된 사용자 흐름, 검증 결과, 남은 에셋/백엔드 연결 항목만 간단히 적어줘.
```
